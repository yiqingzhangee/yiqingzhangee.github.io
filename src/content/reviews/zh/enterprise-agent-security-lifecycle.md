## 核心判断

1. 智能体安全的边界已经超出模型输出；身份、记忆、工具和下游系统都在控制范围内。[1]
2. 需求、构建、测试、部署、运行、变更和退役均需独立门禁；版本、权限或工具变化后，相关证据与回滚条件必须重新验证。[4]
3. 高风险动作应由模型外控制平面裁决，并以短期凭据、最小权限、沙箱和人工批准限制影响范围。[2]
4. AgentLAB 的 644 个用例和运行期 MCP 工具变更表明，一次性验收无法覆盖长程任务与组件漂移。[9][13]
5. 企业应先在低自治、可逆场景积累运行证据，再逐级放权；重大事件应触发自动降级。[16]

本文研究企业级智能体安全体系，覆盖身份、上下文、记忆、工具、动作、评测和治理。事实依据来自公开标准、政府指南、厂商漏洞记录与论文原文；阶段划分与控制组合属于工程建议，不是任何标准的官方映射。公开漏洞和学术评测共同支持“风险已进入真实行动链”这一判断。90、180、365 天实施节奏是可行性规划，企业须按行业、监管辖域与业务损失上限重新校准。

## 一、边界与威胁：风险已进入行动链

模型的概率性判断一旦接入身份、数据与执行环境，安全对象就扩展到整条行动链。低信任内容可在上下文中影响规划，再经工具调用放大为数据外泄、越权写入或代码执行。

### 1.1 安全对象与信任边界

AI 智能体通常由大语言模型驱动，可以规划、调用工具、保持记忆并采取行动。普通大模型应用主要输出文本；智能体还持有目标、触发器、身份、凭据、运行上下文、工具接口与可变状态。OWASP 因而将目标劫持、工具误用、身份滥用、记忆投毒、代码执行和级联故障纳入安全范围。[1] 多国网络安全机构的联合指南也将模型、外部数据源、记忆、规划工作流和工具视为整体系统。[2]

![智能体行动链中的资产与信任边界](/images/reviews/agent-security/agent-security-trust-boundaries-zh.png)

*图 1：资产与信任边界沿行动链展开，模型只是其中一层。来源：OWASP [1]；多国联合指南 [2]。*

控制目标也随之改变：安全团队需要知道谁在行动、依据哪些上下文、调用哪个版本的工具、访问什么数据，以及产生哪些不可逆影响。执行授权应位于智能体上下文之外；审批必须绑定主体、工具、参数与时效，任一参数变化都触发重新裁决。若由模型自行判断是否获批，提示注入仍可影响这一决定。[1]

### 1.2 上下文污染如何变成真实动作

间接提示注入利用了同一上下文中数据与指令难以可靠分离的问题。网页、邮件、文档、检索结果和工具返回原本只是待处理数据，模型却可能把恶意文本解释为更高优先级的任务。OWASP 指出，检索增强生成（RAG）与微调不能彻底消除这类风险，后果可延伸至未授权数据访问和下游命令执行。[6]

| 攻击面 | 进入路径 | 放大机制 | 可见后果 |
| --- | --- | --- | --- |
| 间接提示注入 | 邮件、网页、文件、工具返回 | 将外部数据误判为控制指令 | 目标劫持、敏感读取、外联 |
| RAG 污染 | 恶意文档进入知识库 | 召回结果持续影响回答与决策 | 定向错误答案、策略误导 |
| 记忆投毒 | 内容被抽取为长期“偏好” | 跨会话延迟触发并伪造先例 | 绕过拒绝、泄露敏感数据 |
| MCP 工具投毒 | 工具描述、服务端元数据 | 工具影子化与批准后变更 | 凭据窃取、越权调用、代码执行 |
| 长程任务攻击 | 多轮消息与连续工具观察 | 将有害目标拆成多个低风险步骤 | 组合危害、审计难以关联 |

*表 1：风险沿“外部内容 → 上下文 → 规划 → 工具 → 结果”逐段放大。来源：OWASP [6]；AgentLAB [9]。*

InjecAgent 包含 1,054 个间接提示注入用例，覆盖 17 类用户工具、62 类攻击者工具和 30 个智能体。[7] PoisonedRAG 的实验显示，在百万级知识库中注入 5 篇恶意文本，可使目标问题攻击成功率超过 90%。[8] 两项研究的测试环境不同，结果不能直接当作生产发生率；它们说明少量污染内容足以改变后续工具决策。

### 1.3 工具链、长程任务与真实漏洞

公开漏洞表明这些攻击已出现在生产系统。EchoLeak（CVE-2025-32711）将恶意邮件、提示注入检测绕过、Markdown 链接处理和自动图片加载串成零点击外泄链；Microsoft 将其登记为 M365 Copilot 信息披露漏洞。[10][11] Context7 的 CVE-2026-75130 则表明，普通文档查询也可能接收被污染的 MCP 指令，随后外泄环境文件凭据并删除文件。[12]

MCP 工具描述还存在“批准后变更”问题：服务器可在首次获信任后修改工具描述，或以恶意工具遮蔽同一客户端内的可信工具；安装时通过审查并不保证运行期持续可信。[13] mcp-remote 的 CVE-2025-6514 表明，连接组件本身也可能成为远程代码执行入口。Docker 的复盘引用 CVSS 9.6，并点名 Claude Desktop、VS Code 与 Cursor 等调用链。[14]

自主规划延长了攻击窗口。AgentLAB 在 28 个真实工具环境中构造 644 个安全用例，覆盖意图劫持、工具链式组合、任务注入、目标漂移和记忆投毒；论文发现单轮防御难以可靠迁移到长程任务。[9] 2026 年 10 月发布的分阶段提示注入研究还在 Claude Code 与 Codex 原生运行时确认了 8 类工作流、7 种攻击目标和 6 个注入面。[25] 审计因此必须理解动作序列和最终数据流：单独看似安全的调用仍可能组合出有害结果。

## 二、生命周期：七阶段均需安全门

模型、提示词、数据源、工具、权限或编排发生变化时，安全门都要重新工作。门禁必须留下可核验证据，包括责任人、批准版本、测试结果、风险接受记录、回滚条件和退役证明。

![七阶段生命周期安全门](/images/reviews/agent-security/agent-security-lifecycle-gates-zh.png)

*图 2：七阶段安全门形成可回流闭环，变更会将系统重新送回评测。来源：NIST AI RMF [4]；多国联合指南 [2]。*

### 2.1 需求、构建与测试

需求阶段应先限定任务，再讨论能力。首批上线场景宜满足目标明确、数据范围可控、动作可逆、损失上限可估计四项条件。系统登记至少包含责任人、目标、触发器、模型、记忆、数据源、工具、凭据、下游系统和禁止动作。多国联合指南要求从低风险任务起步，并在设计阶段完成威胁建模、权限限制、沙箱、限流、短期凭据与人工复核设计。[2]

构建阶段要求所有影响行动的组件可追溯：模型、系统提示、策略、工具描述、MCP/A2A 连接器、记忆结构、依赖包和数据集均须版本化。密钥扫描、依赖审查、权限复核与授权中间件检查通过后，系统才能进入集成测试。记忆写入还须验证来源、隔离用户与会话、设置过期时间并记录完整性摘要。[1]

测试既要覆盖正常任务，也要覆盖滥用路径。直接和间接提示注入、工具越权、数据外泄、记忆投毒、多智能体级联、意外代码执行、资源耗尽和高影响动作均应进入用例矩阵。门禁除记录攻击能否成功，还须报告正常任务完成率、误拦率、人工批准负担和失败时的影响范围。AgentDojo 同时评估安全与效用，提供 97 个真实任务和 629 个安全用例，可作为双目标测试基线。[19]

### 2.2 部署、运行、变更与退役

部署门应确认生产隔离、短期凭据、集中策略执行点、限流配额、动作预览、审计轨迹、回滚和紧急停止均可用。高影响或不可逆操作在执行前展示精确参数，并取得明确批准；审批一经使用即失效。部署完成只说明一个版本获准运行，后续变更仍须复验。

运行阶段对每次特权调用重新验证身份、授权和上下文。应关注权限突增、工具序列偏离、异常资源消耗、敏感读取后外联、护栏绕过和跨智能体级联等信号。超过阈值时，系统自动降权、隔离会话或停止执行，再触发人工响应。NIST 将治理置于 MAP、MEASURE、MANAGE 三类活动之上，要求风险识别、测量与处置贯穿生命周期。[4]

模型、提示词、策略、数据源、工具、权限或依赖的变化都可能改变攻击面。变更门须重做差异化威胁建模、回归与对抗测试、权限复核和分阶段发布。退役时应撤销智能体及子智能体凭据，解除触发器和路由，处理记忆与向量数据，确认不存在孤儿授权，并保留审计与取证证据。NIST 生成式 AI 画像明确要求建立安全退役流程和按风险排序的系统清单。[5]

## 三、防御架构：外部控制面裁决行动

模型侧检测可减少恶意输入，确定性授权阻止越权动作，隔离与最小权限限制损失范围，可观测和回滚处理漏网事件；四类控制必须同时存在。

![模型外智能体行动控制面](/images/reviews/agent-security/agent-security-action-control-plane-zh.png)

*图 3：控制平面以身份和策略为主轴，贯穿上下文、工具、执行与响应。来源：CSA Agentic Trust Framework [16]；OWASP [6]。*

### 3.1 身份、凭据与策略执行点

每个智能体、子智能体和工具连接器均需独立身份，并绑定所有者、用途、能力清单和环境。凭据按任务签发，期限要短，资源与动作范围要窄；读、写、删除、支付、发布和外联应拆分为独立权限。CSA 建议从唯一标识和加密凭据起步，在更高自治阶段增加 OAuth2/OIDC、基于属性的访问控制（ABAC）与策略即代码。[16]

策略执行点位于模型与真实工具之间。它接收结构化调用请求，再按主体、任务、数据敏感度、工具版本、参数、时间和风险评分作确定性裁决。未知工具、缺失审批、参数漂移与越界资源默认拒绝。对高影响动作，模型只能提出候选操作，独立规则和人工批准共同决定是否执行。

### 3.2 上下文、记忆与工具隔离

输入防护应标记来源并降低污染概率，包括 schema 校验、内容净化、提示注入检测、敏感信息识别和数据血缘。外部内容应携带信任标签进入上下文；系统指令、用户目标与第三方数据分区处理。输出防护负责校验结构、敏感数据和允许动作，避免模型将未经授权的信息直接交给工具。

记忆与 RAG 需要独立治理：写入前校验来源和内容，按租户、用户、会话隔离，设置过期与容量限制，并保留文档 ID、入库时间、召回排名和最终证据链。对高风险知识库设置可信快照与 canary 问题，发现污染后可隔离条目、重建索引并回放受影响时段的工具调用。PoisonedRAG 的少量文档投毒结果说明，仅靠抽样人工审阅无法形成充分保证。[8]

工具与执行环境应采用白名单、网络出口控制、文件系统隔离、资源配额、单次交易上限和累计影响上限。浏览器、代码执行、数据库写入与支付工具分别置于不同沙箱和凭据域。MCP 服务的工具描述、schema、二进制和来源均须锁定版本并监测变更，防止批准后的内容变化绕过安装审查。[13]

### 3.3 监控、人工门与可恢复性

全链路日志至少关联智能体身份、会话、输入来源、记忆写入与召回、规划摘要、工具版本、参数、返回值、审批记录、网络去向和最终副作用。Microsoft 的 AI 安全基准将异常 API 用量、非预期模型输出和不规则数据访问列为可操作信号，并建议与 MITRE ATLAS、OWASP 等威胁情报关联。[21]

检测必须关联从来源到结果的完整链路。EchoLeak 的攻击过程是低信任邮件进入上下文，随后读取内部高敏感数据，并自动访问攻击者资源；每个单点可能看似正常，串联后却明确指向外泄。[10] 多个低风险工具调用若共同产生高风险结果，也应由序列级策略阻断。

响应能力决定失败会造成多大损失。最低要求包括撤销会话、轮换凭据、隔离连接器、停用工具、人工紧急停止、回滚动作和从可信状态恢复。CSA 提出的目标包括自动熔断、人工停止时间小于 1 秒、条件允许时回滚动作，以及故障时降至更低自治级。[16] 这些目标必须在真实基础设施上实测，不能直接视作通用服务等级协议。

## 四、攻防运营：评测跟着系统变化

上线前红队只能确认某一版本在一组攻击下的表现。模型更新、工具描述变化、知识库写入和攻击策略适配会持续改变风险，评测、检测、阻断、取证和规则回灌必须常态运行。

![持续 TEVV 安全闭环](/images/reviews/agent-security/agent-security-continuous-tevv-zh.png)

*图 4：持续攻防将红队、门禁、运行时检测、响应与规则回灌连成闭环。来源：NIST AI RMF Playbook [17]；MITRE ATLAS [20]。*

### 4.1 四层评测覆盖组件到生产

持续评测可分四层：组件层验证模型、提示词、记忆、工具、策略和依赖；近真实环境层复现生产身份、权限、数据与网络；端到端层执行间接注入、越权、外泄、长程组合和恢复测试；生产层持续执行 testing、evaluation、verification 与 validation（TEVV），再把真实事件和未遂事件加入测试集。这是对 NIST MEASURE/MANAGE 建议的工程化归纳，并非 NIST 原生等级命名。[18]

测试集既需固定回归用例，也需动态生成用例。固定集用于比较版本变化；动态集引入最新攻击、随机化语义、不同工具序列和多轮适配。AgentLAB 表明，单轮防御无法稳定覆盖跨会话和长程任务。[9] MCP 工具还能在批准后修改描述，因此供应链版本漂移也要进入生产期回归。[13]

### 4.2 指标同时约束安全与业务效用

| 维度 | 核心指标 | 检测信号 | 触发动作 |
| --- | --- | --- | --- |
| 攻击有效性 | 攻击成功率、越权调用率、敏感源到汇完成率 | 目标漂移、异常工具序列、敏感读取后外联 | 阻断、降权、隔离 |
| 正常效用 | 任务完成率、正确工具率、用户纠正率 | 拒绝激增、重复规划、超时 | 回滚版本、调整策略 |
| 运营代价 | 误拦率、人工批准率、每任务成本 | 审批堆积、令牌或调用量异常 | 收窄场景、优化门槛 |
| 韧性恢复 | 发现时间、响应时间、恢复时间、回滚成功率 | 熔断失败、日志缺口、状态不可重建 | 停止服务、进入事件响应 |

*表 2：评测同时报告安全、效用、运营代价与恢复能力。来源：NIST [18]；AgentDojo [19]。*

单一攻击成功率不能代表生产安全。前沿模型在没有攻击时也会失败，单一攻击只覆盖部分安全属性，防御也可能通过大量误拦“改善”安全数字。NIST 同样警告，指标可能被过度简化、被博弈或脱离原始语境。[18] 每项上线门槛都应写明测试环境、攻击能力、工具权限、数据敏感度、置信区间和业务效用底线。

### 4.3 事件响应推动规则回灌

事件响应依次处理遏制、取证、清除、恢复和复盘。对 Context7 类事件，应先隔离恶意 MCP 源与会话，轮换可能暴露的环境凭据，再审计文件操作并从可信状态恢复。[12] 对记忆投毒，删除当前会话并不足够；还应按来源和写入时间定位污染记忆，检查其在后续会话中的召回与动作影响。

复盘结果须落实到威胁模型、策略执行点和评测集。MITRE ATLAS 根据真实攻击观察和红队演示持续更新，可用于统一战术技术分类与检测覆盖口径。[20] NIST 建议按固定频率开展红队，并用事件与测试结果修订安全流程。[17] 同类事件能否更早被发现并自动阻断，是检验闭环是否有效的直接标准。

## 五、治理落地：分级授权换取扩展

权限应随运行证据增加。智能体先在低自治状态证明业务价值和控制有效性，再依据运行记录、安全验证、事件表现与治理签字提升自治；重大事件触发自动降级。

### 5.1 四级自治对应不同上线门槛

| 自治级别 | 允许行为 | 最低控制 | 晋级证据 |
| --- | --- | --- | --- |
| L1 只读观察 | 读取、分析、提出建议 | 身份、数据边界、全量日志 | 稳定任务完成率与零敏感写入 |
| L2 建议后批准 | 生成动作，逐项人工批准 | 精确动作预览、一次性审批 | 低误报、批准质量与可回滚 |
| L3 护栏内执行 | 批准域内执行并事后通知 | 策略即代码、限额、异常熔断 | 连续运行、安全测试、零严重事件 |
| L4 域内自治 | 在批准领域自主规划与执行 | 持续验证、独立监控、自动降级 | 多方治理签字与定期再认证 |

*表 3：自治权限由运行证据换取，重大事件触发降级。来源：CSA Agentic Trust Framework [16]。*

CSA 给出的示例阈值是：只读级至少运行 2 周，批准级至少运行 4 周且建议接受率超过 95%，通知级至少运行 8 周且没有严重事件。[16] 企业不能直接照搬这些数字。金融转账、生产变更、人员处置和高敏感数据导出等场景需要更长观察期，并长期保留人工批准。

### 5.2 90、180、365 天实施路线

- **0 至 90 天：** 完成智能体、工具、凭据与数据资产清单；为每个智能体建立唯一身份；接入策略执行点、短期凭据、全链路日志与紧急停止；选择一至两个低风险场景在 L1/L2 运行；建立提示注入、越权与外泄的首批回归用例。CSA 的工程顺序同样将身份、数据治理、行为监控、隔离和事件响应依次置于前五周。[16]
- **91 至 180 天：** 将 TEVV、固定频率红队和第三方组件复核纳入发布流程；建立生产异常检测、SOC 联动、凭据轮换和记忆/RAG 污染处置；演练隔离、降级、回滚与恢复；依据实测结果调整 L2/L3 门槛。[17]
- **181 至 365 天：** 扩展策略即代码与跨环境证据留存；复审风险容忍度和指标有效性；重新认证供应商、模型与工具；完成退役及恢复演练；对高风险领域引入独立审计，并决定是否开放 L4。

身份和边界建设应先于行动权限扩张。若日志无法关联主体与动作，策略无法在模型外强制执行，或系统无法回滚，继续提升自治只会扩大无法解释和控制的风险。

### 5.3 责任、合规与停止条件

治理责任至少涉及业务所有者、产品与工程、安全、隐私与法务、模型风险、供应商管理和事件响应。业务所有者定义允许目标与损失上限；安全团队维护威胁模型、策略和检测；工程团队负责隔离、回滚与日志；模型风险团队维护评测；供应商管理负责组件清单、漏洞通道和退出预案。NIST 要求明确设计、开发、部署、评估、监控与更新人员的职责和授权委派。[17]

停止条件应在上线前写入：风险指标超过容忍度、严重事件、监控失效、工具或供应链来源不明、关键日志缺失，或存在无法及时缓解的迫近风险。触发后先旁路或停用，再保留取证材料、执行根因分析并满足重新上线标准。欧盟 AI Act 对高风险 AI 还要求人工监督，并在特定风险或严重事件条件下暂停使用和通知相关方。[22] 某一智能体是否属于高风险类别，仍须按用途、角色和辖域判断。

## 六、综合判断：小步验证后扩大自治

公开漏洞证明，风险已经到达数据、凭据和代码执行层。NIST、OWASP、CSA 与多国联合指南均要求最小权限、独立授权、持续监测、人工门和可恢复性。相关技术组件已经可用，但系统级保证仍须在真实业务中逐级验证。

### 6.1 成熟度按可控行动递进

成熟度可分为五项连续能力：资产可见、身份可辨、行动可裁决、结果可恢复、风险可持续演进。前一项尚未建立时，后一项就缺少可信证据。模型过滤器无法替代身份和策略执行点；日志没有回滚能力时只能解释事故；只做上线前红队也覆盖不了知识库与工具供应链的运行期漂移。

现有框架需要组合使用：NIST AI RMF 与 ISO/IEC 42001 适合作为治理和生命周期外壳；[4][23] OWASP AI Agent Security Cheat Sheet 提供本文采用的智能体风险分类与运营控制，[1] OWASP Top 10 for Agentic Applications 则补充应用风险清单；[15] MITRE ATLAS 支撑对手战术、红队与检测映射；[20] CSA 补充身份、自治分级和事件控制。没有一个框架能单独覆盖治理、工程控制、攻击知识与运行保证。

### 6.2 采用建议与适用边界

实施应先小步验证，再扩大自治。首批场景选择只读或逐项批准、数据范围明确、动作可逆、损失上限可估计的任务。最小控制平面建立后，再以正常任务完成率、安全用例、人工负担、事件记录和恢复演练决定是否晋级。高影响、不可逆或跨域行动应长期保留独立策略裁决与明确人工批准。

进入高自治前，智能体和工具必须有独立身份；凭据必须能按任务缩小权限与时效；工具调用必须能在模型外被拒绝；上下文、记忆和工具版本需要可追溯；异常后能够立即停止并恢复；持续评测必须覆盖真实权限和长程任务。满足这些条件仅代表具备试点基础，最终仍须以生产证据证明风险处于业务容忍度之内。
